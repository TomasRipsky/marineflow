A data-engineering project on the live AIS feed

Which vessel just did something impossible?
And which ones have looked suspicious all month?

MarineFlow ingests every ship position broadcast worldwide and answers both questions from the same stream: one in seconds, the other once an hour.

One stream, two speeds

Hot path · seconds

“Is this ship doing something impossible, right now?”

A Spark job keeps per-vessel state and compares every position with the previous one. A ship that appears to travel faster than 35 knots, accelerates absurdly, or goes silent for two hours raises an alert on vessel-alerts — Kafka to Kafka, with no warehouse in the way.

  • Stateful: applyInPandasWithState
  • Tolerates AIS “not available” sentinels
  • State survives restarts (checkpoint volume)
Cold path · hourly

“Which vessels looked suspicious over 30 days?”

The same positions are archived as Parquet in Google Cloud Storage, read through BigQuery external tables, and modelled by dbt into seven gold tables: dark events, speed anomalies, loitering, erratic course, activity, port traffic and a 30-day risk score. Airflow runs it every hour.

  • Bronze → Silver → Gold (medallion)
  • Incremental merges with surrogate keys
  • 104 dbt data tests after each run

Design decisions worth explaining

A compaction that cannot lose data

The first version read a Silver partition and overwrote the same path. Measured in the Spark image: 6 files and 600 rows became 0 and 0, while a catch-all except reported a warning. It was removed.

The replacement snapshots the partition, stages the result outside the table prefix, verifies it, commits through a manifest, and rolls forward after a crash. Late files are never read or deleted.

Tests that check the seams

Most bugs here were not inside a layer but between two. So the tests compare layers: Terraform external-table schemas against what the Spark jobs write, the DAG against the dbt models, Compose against the variables the code reads, and the README's numbers against the repository.

The smoke tests run on real Spark, because a fake had hidden a crash that only real Spark produced.

Dashboards as code

The four Grafana dashboards are generated by one stdlib-only Python script and committed as JSON. A unit test fails if the JSON drifts from the generator, if a panel points at a datasource that is not provisioned, or if a cluster-wide query leaks Kafka's internal __consumer_offsets topic.

Limits, stated plainly

  • Spark runs in local mode, one container per job, started by hand. Nothing restarts a job that dies, and on a small Docker VM the kernel can kill one silently. Production would use Dataproc or GKE.
  • The reference lookups are coarse. Flags come from 65 MID codes (35 countries); ports are 15 bounding boxes; ocean regions are boxes too.
  • No ship-to-ship transfer detection. An earlier flag could never be true and was removed instead of kept as decoration.
  • Silver deduplicates and computes deltas per micro-batch, not across batches.
  • aisstream.io is in beta, with no SLA.
